# 重新规划：从「求职分析看板」到「投递自动填表助手」

> 状态（2026-10-02）：P1–P4 已实现，见 [CHANGELOG](../CHANGELOG.md) 和 [README](../README.md)。下面保留规划原文。

## 1. 要解决的真问题

投递时最浪费时间的不是“分析岗位”，而是**每个网申系统都要重新填一遍同样的信息**：

- 国内：大厂/国企网申（北森、Moka、飞书招聘、大易、智联/前程无忧网申页）反复填基本信息、教育、实习、项目、获奖、语言成绩、期望薪资、到岗时间……
- 澳洲：Workday（每家公司都要重新注册并逐段录入经历）、Greenhouse、Lever、SmartRecruiters、SuccessFactors，以及 Seek / LinkedIn 的额外问题（work rights、visa、notice period、salary expectation）。
- 开放题（“为什么想加入我们”“Why this role”）每次都要现写。

**新目标：一份资料填一次，之后每个网申页面一键填好，人只负责检查和点提交。**

## 2. 新的产品形态

```
┌────────────────────┐      ┌──────────────────────┐      ┌─────────────────┐
│ ① 求职资料库        │      │ ② 浏览器插件          │      │ ③ 投递记录       │
│ (本地 Web UI)       │ ───▶ │ 在网申页面一键填表     │ ───▶ │ 自动记一笔       │
│ 中文版 + 英文版      │      │ 开放题 AI 起草        │      │ 状态 / 跟进      │
└────────────────────┘      └──────────────────────┘      └─────────────────┘
        ▲ 上传简历 PDF，AI 解析成结构化资料（可手动修改）
```

### ① 求职资料库（填一次）

一份结构化 profile，**中英两套**（国内网申用中文，澳洲用英文，插件按页面语言自动选）：

| 分组 | 字段示例 |
| --- | --- |
| 基本信息 | 姓名 / 英文名 / 拼音、电话（+86 / +61）、邮箱、性别、出生日期、所在城市、地址、LinkedIn、GitHub、作品集 |
| 国内常见 | 民族、政治面貌、籍贯、户口所在地、最高学历、是否应届、毕业时间、是否接受调剂 |
| 澳洲常见 | Work rights / visa 类型与到期日、是否需要 sponsorship、notice period、availability、salary expectation（AUD） |
| 教育经历（多段） | 学校、专业、学位、起止时间、GPA/排名、主修课程 |
| 工作/实习（多段） | 公司、职位、起止时间、地点、描述（中英） |
| 项目（多段） | 名称、角色、时间、技术栈、描述 |
| 技能 / 证书 / 语言 | CET-4/6、IELTS/PTE、编程语言、证书 |
| 获奖 / 校园经历 | 名称、时间、级别 |
| 常用问答库 | 自我评价、优缺点、期望薪资、到岗时间、为什么选择我们（模板）…… |
| 附件 | 中文简历 PDF、英文简历 PDF、成绩单 |

**录入方式**：上传简历 PDF → AI 抽取成上面的结构 → 用户在表单里确认、修改。没配置 AI 时可以手填。

### ② 浏览器插件（核心）

Chrome / Edge 扩展（Manifest V3），在用户自己的日常浏览器里用，登录状态都是现成的。

1. 打开任何网申页面 → 点插件「一键填写」
2. 插件识别页面上的表单字段（label / placeholder / name / aria / 附近文字）→ 映射到资料库字段
3. 侧边栏显示填写预览：✅ 已填、⚠️ 不确定（标黄让你看）、❓ 没识别
4. 多段经历自动点「添加一段」并逐段填
5. 简历附件自动上传到 file 输入框（支持的网站）
6. 开放题：读当前页面的 JD + 你的资料，AI 起草答案，你确认后填入
7. **你手动改过 / 新填的答案，插件问「记住吗？」** → 写入问答库，下次同类问题直接填
8. 永远不自动点「提交」；你点提交后插件弹一下「记录这次投递？」→ 写入投递记录

**字段识别分三层**（从快到慢）：
- 站点适配器：Workday、Greenhouse、Lever、北森、Moka、飞书招聘等常用 ATS 写专门规则，准确率最高
- 通用规则：中英文同义词表（“手机号码 / 联系电话 / Mobile / Phone”）+ input 类型
- AI 兜底：剩下识别不了的字段，把 label 列表发给大模型做映射

### ③ 投递记录

保留现有 `application_tracker`，只保留：公司、岗位、链接、日期、状态、下次跟进。插件自动写入，Web UI 一个列表页查看。

## 3. AI 用在哪里（只用在真正省时间的地方）

| 场景 | 说明 |
| --- | --- |
| 简历 PDF → 结构化资料 | 一次性，省去手动录入 |
| 中文资料 → 英文版 | 一键翻译成澳洲风格的英文描述，再人工改 |
| 开放题作答 | 结合 JD + 资料库起草 |
| 字段映射兜底 | 规则识别不了的表单字段 |
| 求职信 / 招聘方消息（可选） | 保留，但不再是主流程 |

模型接入做成可配置：OpenAI 兼容接口（DeepSeek、通义千问、Kimi、OpenAI 都能用）+ Claude。API Key 存在本地 `.env`，不进 Git。

## 4. 现有功能怎么处理

| 现有功能 | 处理 |
| --- | --- |
| 简历 PDF 解析 (`rag/resume_index.py`) | 保留 PDF 文本提取，改为喂给 AI 做结构化 |
| 投递记录 (`application_tracker.py`) | 保留，精简字段 |
| 岗位链接读取 (`job_url_reader.py`) | 保留，给开放题 / 求职信提供 JD |
| 关键词打分 (`matcher.py`)、模板草稿 (`draft_generator.py`) | 由 AI 替代，旧代码删除 |
| QQ 邮箱扫描、邮件复查队列、扫描诊断 | 移出主流程（先删掉 UI，代码归档） |
| 书签小工具导入、Playwright 登录浏览器导入 | 由插件替代，删除 |
| 首页统计卡片、目标模式、JD 完整度检查、流程步骤卡 | 删除 |
| 4551 行的 `App.tsx` | 重写为 3 个页面：资料库 / 投递记录 / 设置 |

## 5. 新界面（Web UI 只剩 3 页）

```
┌──────────┬───────────────────────────────────────────┐
│ 资料库    │  [中文] [English]          [上传简历自动识别] │
│ 投递记录  │  ─────────────────────────────────────────  │
│ 设置      │  基本信息   ▸ 张三 · 138xxxx · xx@qq.com     │
│          │  教育经历   ▸ 2 段                          │
│          │  实习经历   ▸ 3 段                          │
│          │  项目经历   ▸ 2 段                          │
│          │  常用问答   ▸ 12 条                         │
│          │  附件       ▸ 中文简历.pdf / English.pdf    │
└──────────┴───────────────────────────────────────────┘
```

- 每个分组折叠显示一行摘要，点开才编辑
- 不放说明文字，空状态只给一个按钮
- 设置页：AI 模型 / API Key、插件连接状态

## 6. 分阶段实施

| 阶段 | 内容 | 完成后你能用到什么 |
| --- | --- | --- |
| **P1 资料库** | 后端 profile 数据结构 + API（本地 JSON 存储）；新前端资料库页面（中英两套）；清理旧功能 | 有一份完整、可编辑的求职资料 |
| **P2 插件 MVP** | MV3 扩展：通用字段识别 + 一键填写 + 预览侧栏；先适配 Workday、Greenhouse、Lever、北森、Moka | 主流网申页面一键填好基本信息和经历 |
| **P3 AI 接入** | 模型配置；简历 PDF → 资料库；中译英；开放题起草；字段映射兜底 | 不用手录资料，开放题有草稿 |
| **P4 学习与记录** | 「记住这个答案」问答库；提交后自动记一笔投递；更多站点适配器 | 越用越省事，投递自动留痕 |

每个阶段单独提交，做完就能用，不需要等全部完成。

## 7. 安全与隐私

- 所有资料只存在本机 `data/private/`（已在 `.gitignore`）
- 插件只和 `127.0.0.1` 本地后端通信；只有调用 AI 时，才把必要内容发给你配置的模型服务
- 身份证号等敏感字段默认不自动填，需要单独开启
- 插件从不自动点击提交
