## 发现并修复

| 场景 | 原问题 | 修复后的行为 |
| --- | --- | --- |
| 编辑框预选本科，资料库硕士排第一 | 只按表单顺序选择资料，可能混入另一学历 | 用已有学历、学校及日期选择完整记录；没有匹配记录时留空。多个同学历编辑框先分配该学历的记录 |
| 页面学历为硕士、学位为学士，再读入资料库 | 同一资料字段被后出现的值覆盖，混合经历可能被导入 | 生成不可勾选的冲突提示，阻止整段导入，要求先纠正页面 |
| 同校本科和硕士，页面已有硕士卡片 | 只靠学校名称把两条都视作已存在 | 重名经历结合入学日期识别，空编辑框仍填写本科 |
| Element Plus 首段填入学校后新增第二段 | 下拉框显示文字被识别成已保存卡片，漏添加第二段 | 已保存卡片扫描排除自定义下拉、日期等控件文字；原完整测试复现失败，修复后两段均填写 |
| 新增弹窗只有 Submit、Apply 或提交按钮 | 原保存按钮识别可能自动提交 | 不点击这些按钮，填写后提示用户保存；三种标签分别验证未点击 |
| 快速双击“存入资料库” | 重复请求造成重复新增经历 | 保存期间禁用按钮并检查忙碌状态，只发送一次请求 |
| 后端返回写入零项 | 面板仍显示成功并丢掉待确认列表 | 显示未写入提示并保留列表；部分写入也明确提示复查 |
| 面板打开后修改资料，立即再次填写 | 后台缓存仍使用旧资料 | 每次全页或单字段填写前刷新后端资料 |
| 两个线程同时导入、上传附件或保存投递记录 | 读改写互相覆盖，共用临时文件可能导致异常 | 单 API 进程内串行修改，独立临时文件写完后原子替换；并发测试核对两项均保留 |
| 旧资料库页面自动保存，插件已导入新资料 | 整份保存覆盖新数据 | 保存携带读取版本，服务端版本不符返回 409；本地编辑保留，界面提示冲突 |
| 切回资料库自动刷新时开始输入 | 延迟的读取结果可能覆盖新编辑 | 未修改时才刷新，返回时再次检查是否已发生编辑或保存 |
| 保存请求尚未结束又继续输入 | 新请求若沿用旧版本会冲突，或旧响应覆盖编辑 | 保留新编辑，并用前次保存返回的新版本继续保存 |
| AI 翻译/起草期间修改、重排或删除资料 | 整份旧结果覆盖编辑、恢复删除条目，或错配翻译 | 只合入未变化的字段或条目；删除及手写内容保留；空条目被后端移除也不会错配 |
