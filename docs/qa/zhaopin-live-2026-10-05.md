## 按现场结构复现并修复

1. 专业输入框是 Element UI 可输入自动补全；根节点持有正确的建议列表 ARIA 标识，输入框的 aria-controls 无效。现在优先使用根节点所属列表，等待异步建议；不访问其他下拉列表。没有匹配建议时保留自由输入并标为需要核对；若网站清空文字，报告未接受输入。
2. 教育新增 `degreeCategory`、`overseasStudy`、`minorType`。字段匹配、选择及读取一致；缺资料时留空，不因学校在国内或没有辅修字段就推断“无”。
3. “职位月薪（税前）”原映射为工作职位，“证明人关系”原映射为证明人姓名。新增排除词及明确字段，补齐 `hasReference`、`referenceRelation`、`referenceCompany`；两段工作的本地填写与回读保持独立。
4. 自我评价标题下的“内容”按标题映射到 `basic.selfEvaluation`。普通校园板块的“内容”仍表示该经历描述。
5. “校园工作经历（学生干部经历、学生会工作、社团骨干等）”原映射为组织名称，“受到奖励”原映射为单个奖项名称。现在这些完整问题通过同题常用问答填写或学习，不拆成结构化条目。校园大赛、科研、出版/专利、职业资格及各项考试成绩也只使用同题答案，避免近似问题的内容串用。一般项目不自动认定为科研，缺考试成绩不自行填“无”。
6. “计算机技能”原取计算机等级，“其他技能”原取整段专业技能。增加 `computerSkills`、`otherSkills`，不迁移或推断原资料。
7. 首次新增教育时，选学历和其他选项会重建控件，原固定两轮填写仍漏掉日期与尾部选项。本地模拟连续三次控件重建，旧版稳定漏填；改为最多八轮重新发现未处理控件，稳定后立即停止，新增/保存流程不重复。重建后保留先前填写的结果、更新定位并去重。再次在真实页面验证一次填写完成，读取建议为空。
